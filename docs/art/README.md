# Art wave 1: models and item sprites

Built by the Art department for Ruhan's request: "start development and create some more models... use any existing models you can find online as bases... for items and their sprites."

## How to rebuild and check

Run these from the repository root with Python 3 and `tools/requirements.txt` (Pillow, NumPy):

```
python3 -I tools/modelgen/modelgen.py build     # geo, animations, entity textures (+ the 7 checks)
python3 -I tools/artgen/artgen.py build         # item icons and item models
python3 -I tools/artgen/credits.py write        # credits.json, then the provenance check
python3 -I tools/modelgen/preview.py sheets     # contact sheets in docs/art/previews/
python3 -I tools/artgen/artgen.py check         # palette lint and every texture against the rules
```

Two consecutive builds give byte-identical files.

**How a "proportion reference" works.** `tools/modelgen/import_glb.py` measures the found glTF and writes `art-src/found/<asset>/measure.json`. That file holds head carriage, tail length and torso ratios, and the species file records which ratios it used. The cube model, texture and animations are generated, and no mesh from the found model ships. Its original is identified by URL, mirror commit and SHA-256 in `source.json`. It is not committed, because the repository has no Git LFS yet.

**How a found sprite works.** Each source colour maps to one ramp step, or to the #1a1512 outline. The original pixel clusters and shading survive, but every pixel lands in the palette.

## Rigs and ids

- **Ids follow DV3.** The grizzly is `grizzly` (not `grizzly_bear`) and the gray wolf is `wolf`.
- **Paths follow DV3:**
  - geometry at `assets/yearofice/geo/entity/<id>.geo.json`;
  - animations at `animations/entity/<id>.animation.json`, with names `animation.<id>.<name>`;
  - textures at `textures/entity/<id>/<variant>_<coat>.png`.
- **Birds share `rig_grouse`.** Its animations are copied to `willow_ptarmigan` and `spruce_grouse`.
- **Cubs, calves and fawns have their own geometry** (`<id>_cub`, `moose_calf`, `<id>_fawn`) with the adult's bone names. The renderer can swap the model by age class, so the young get juvenile proportions and not only a scaled-down adult.
- **The cervid rig has 38 bones, as the deer sheet (T21) asks.** `neck_swell` and the tines `antler_<side>_brow` and `_g2` to `_g5` are bones. That is over the Large tier's 32-bone cap, so `modelgen` gives the cervid rig its own cap of 38.
- **Rotation conventions** are documented in `tools/modelgen/geo.py`. A positive X rotation pitches nose-down (Bedrock `look_at_target`). A drooping tail is stored as a negative X rotation.

## G2 pass: bears and grouse (RECONCILE 157)

The Director's look check sent the grizzly, black bear and the grouse rig back for a Blockbench polish. The edits were made in Blockbench (Bedrock Entity format) on the imported G1 geometry, inside the existing bones, and exported to `tools/modelgen/overrides/<geo_id>.geo.json`. The `.bbmodel` working files sit next to them in `overrides/blockbench/`, and `overrides/README.json` says why each override exists.

**How an override builds.** A species file names it with `"override"`. `modelgen` refuses it unless every bone name, parent and pivot equals the template's, so the generated animations still bind. It then re-packs the UVs, paints every cube from the palette ramps (the bone's paint glob, or `cube_paint` keyed `"bone#index"`), resolves coplanar faces in model space (rotated bones and cubes included), and runs the same seven checks. Paint ramp `"none"` leaves a cube clear, which GeckoLib's cutout render type hides.

**Paint.** Spruce grouse male: grey above with pale bars, black throat, breast and belly front (`fur_black`), a bright `comb_red` comb; the outer fan is dark with a pale tip. Female: all ramps remapped to `feather_grouse_female` with barring. Ptarmigan: the outer fan is painted `"none"`, so its tail stays narrow; the comb shows in winter only, as before.
